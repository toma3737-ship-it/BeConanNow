# BeConanNow — ربط Supabase (نسخة تأسيسية)

هذه الحزمة تضيف ربطًا أوليًا بقاعدة بيانات Supabase ولوحة إدارة عربية. لا تحتوي على عنوان مشروعك أو مفاتيحه.

## الملفات الجديدة
- `admin.html` و`admin.js`: تسجيل دخول المسؤول ونموذج إنشاء القضايا والمشتبهين والأدلة والتلميحات والحل.
- `supabase-config.js`: ضع فيه Supabase URL وPublishable key فقط.
- `supabase-setup.sql`: يضيف الحقول المطلوبة ودالة للتحقق من الإجابة وكشف التفسير بعد الإرسال، دون منح الواجهة قراءة مباشرة لجدول الحلول.
- `.gitignore`: يمنع تتبع `node_modules` مستقبلًا.

## خطوات الإعداد
1. خذ نسخة احتياطية من مشروعك الحالي.
2. انسخ ملفات الحزمة إلى مجلد المشروع، مع استبدال الملفات المطابقة عند الطلب. لا تحذف ملفات المشروع الأخرى.
3. في `supabase-config.js` ضع Supabase URL وPublishable key من مشروع **BeConanNow** فقط. لا تضع `service_role` أو أي مفتاح سري في هذا الملف.
4. في Supabase SQL Editor، راجع وشغّل `supabase-setup.sql` مرة واحدة.
5. افتح `admin.html` على موقعك بعد النشر، وسجّل الدخول بحسابك الذي أضفته إلى `public.admin_users`.
6. أنشئ قضية تجريبية بحالة «مسودة». القضايا المنشورة فقط تظهر للاعبين. يمكنك إنشاء قضية بحالة «منشورة» عند جهوزيتها.
7. اختبر إرسال إجابة من الصفحة الرئيسية. بعد تسليم الإجابة، تعيد قاعدة البيانات نتيجة المطابقة وتفسير الحل. الحل لا يُقرأ مباشرة من الواجهة العامة.
8. بعد الاختبار، نفّذ Commit وPush إلى GitHub Pages.

## تنبيهات
- احتفظ بملفي `package.json` و`package-lock.json`، ولا ترفع `node_modules`.
- يجب أن يكون حساب الإدارة مسجلًا في `public.admin_users`؛ مجرد إنشاء حساب Supabase لا يمنحه صلاحية الإدارة.
- هذه نسخة تأسيسية للعب الفردي. الجولات التنافسية متعددة اللاعبين تحتاج نظام جلسات وإجابات مؤقتة على الخادم قبل إطلاقها.
- النقاط وحفظ التقدم في هذه النسخة ليسا نظام ترتيب تنافسي موثّقًا على الخادم بعد.
- لا تضع أي مفتاح إداري أو كلمة مرور داخل ملفات HTML/JavaScript.
- الموقع يستخدم JavaScript modules عبر HTTPS؛ اختبره عبر GitHub Pages أو خادم محلي، وليس بفتح `index.html` بالنقر المزدوج إذا منع المتصفح استيراد الوحدات.

## ملاحظة حول القضايا التجريبية السابقة
تمت إزالة الحلول والقضايا الثابتة من `app.js` حتى لا تُنشر الإجابات السرية ضمن ملفات الموقع. ستظهر القضايا الجديدة التي تنشئها من لوحة الإدارة. إن أردت إبقاء القضايا التجريبية السابقة، يمكن نقلها إلى قاعدة البيانات بدل ترك حلولها مكشوفة في ملفات الواجهة.


## اللعب الجماعي

أضيفت صفحة `multiplayer.html`، وملف تشغيلها `multiplayer.js`، وملف SQL إضافي `multiplayer-setup.sql`. من الصفحة الجديدة يمكن إنشاء غرفة عبر الإنترنت برابط ورمز دعوة، أو الانضمام بالرمز، واختيار التعاون أو المنافسة. كما يمكن اللعب بالتناوب على هاتف واحد.

### التفعيل الآمن
1. انسخ ملفات هذه الحزمة إلى جذر مجلد المشروع الأصلي، ووافق على استبدال `index.html` و`README.md` عند الطلب. لا تحذف مجلد `.git` ولا تستبدله، ولا ترفع `node_modules`.
2. لا تستبدل `supabase-config.js`؛ احتفظ بإعدادات مشروع BeConanNow الحالية.
3. في لوحة Supabase الخاصة بمشروع BeConanNow فقط، افتح SQL Editor وشغّل محتوى `multiplayer-setup.sql` مرة واحدة. لا تشغّل SQL في مشروع آخر. هذا الملف يضيف جداول ودوال جديدة باسم `bcn_game_*` ولا يحذف القضايا أو الجداول الحالية.
4. ارفع التغييرات إلى GitHub Pages. افتح `https://toma3737-ship-it.github.io/BeConanNow/multiplayer.html` بعد اكتمال النشر.
5. اختبر غرفة من متصفحين مختلفين قبل مشاركة الموقع.

**تنبيه:** هذه إضافة أولية؛ لم أتمكن من تشغيلها ضد قاعدة Supabase الفعلية من هنا. لذلك يجب إجراء اختبار إنشاء غرفة، والانضمام، وتثبيت الإجابة في مشروعك قبل اعتبارها جاهزة للإطلاق العام. لا تستخدم أي مفتاح `service_role` في ملفات الموقع.

## تحديث إصلاح عرض القضية والإجابات المفتوحة

إذا كنت تستخدم نسخة اللعب الجماعي السابقة، شغّل **النسخة المحدّثة من `multiplayer-setup.sql` مرة أخرى** من SQL Editor في مشروع Supabase نفسه. يحتوي الملف على إضافات آمنة (`ADD COLUMN IF NOT EXISTS` ودوال `CREATE OR REPLACE`) لتفعيل:

- إظهار ملف القضية وتفاصيل البلاغ والأشخاص والأدلة والخط الزمني لكل لاعب ينضم إلى الغرفة.
- اختيار نوع الإجابة عند إنشاء القضية: اختيار شخص، أو إجابة مفتوحة مكتوبة.
- إنشاء قضية مفتوحة بلا مشتبهين، مع إجابة مرجعية وشرح سري.
- إرسال الإجابات المفتوحة في اللعب الفردي والجماعي دون تقييم آلي زائف للصياغة.

لا تحذف أي جداول ولا تشغّل SQL على مشروع Supabase آخر. بعد تشغيل SQL، انسخ ملفات ZIP إلى مجلد المشروع مع عدم استبدال مجلد `.git`، ثم ارفع التغييرات إلى GitHub.

- إذا ظهرت القضايا بعد تحديث SQL، اختبر البحث من الصفحة الرئيسية، ثم ارفع صورة وملفًا صوتيًا وفيديو صغيرًا من لوحة الإدارة.


## تحديث اللعب المختلط والجولات (2026-10-20)
- شغّل `hybrid-multiplayer-migration.sql` مرة واحدة في Supabase SQL Editor بعد إعداد اللعب الجماعي؛ يضيف RPC آمنة لا تعرض الحل النهائي إلا بعد تثبيت إجابات جميع لاعبي الغرفة.
- لإنشاء غرفة هجينة، اكتب اسم المضيف، ثم أسماء اللاعبين الموجودين معه على الهاتف نفسه (اسم في كل سطر)، وأنشئ الغرفة بنمط المنافسة. يمكن لبقية اللاعبين الانضمام عبر الرابط أو الرمز. في صفحة الغرفة يظهر اختيار للتبديل بين اللاعبين المحليين على الجهاز.
- تفاصيل القضية تفتح في `case.html` بصفحة مستقلة، وتبقى شاشة الإجابة في صفحة الغرفة.
- في اللعب المحلي، فعّل خيار القضايا العشوائية وحدد عدد القضايا في الجولة؛ يحاول الموقع تنويع التصنيفات وأنواع الإجابة. بعد النتائج يمكنك الانتقال إلى القضية التالية أو بدء جولة أخرى.

## تحديث الجولات العشوائية في اللعب الجماعي عبر رابط الدعوة

أُضيفت إعدادات الجولة العشوائية أيضًا إلى **اللعب الجماعي عبر الإنترنت**، وليس اللعب على الهاتف نفسه فقط:

1. في Supabase SQL Editor شغّل الملف `online-random-rounds-migration.sql` مرة واحدة، بعد أن تكون قد شغّلت ملفات إعداد اللعب الجماعي والتحديث السابق `hybrid-multiplayer-migration.sql`.
2. ارفع ملفات الحزمة إلى GitHub مع الحفاظ على `supabase-config.js` الحالي وإعدادات المشروع.
3. عند إنشاء غرفة جديدة، حدّد عدد القضايا وفعّل خيار الاختيار العشوائي. يختار الموقع قضايا منشورة مختلفة ويحاول تنويع التصنيفات وأنواع الإجابة. يجب أن يكون عدد القضايا المنشورة كافيًا للعدد المختار.
4. يشارك جميع من يدخلون عبر رابط الدعوة في الجولة نفسها. بعد أن يجيب الجميع، يظهر الحل النهائي؛ ثم يستطيع المضيف وحده الانتقال إلى القضية التالية. تُصفّر إجابات القضية السابقة عند الانتقال، وتبقى الغرفة ورابط الدعوة نفسيهما.
5. إذا لم تُفعّل الاختيار العشوائي، تلعب الغرفة القضية المحددة فقط، وبعد انتهاء الجميع يمكن للمضيف بدء إعداد جولة جديدة.

هذا التحديث لا يغيّر جداول القضايا أو الحلول الموجودة، ولا يمنح المتصفح صلاحية قراءة الحلول مباشرة.
